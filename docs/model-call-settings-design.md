# 模型调用与设置设计

日期：2026-10-26  
状态：设计待实施  
范围：在现有本地 Rill 应用中支持 DeepSeek 与智谱 GLM-5.3，管理两家 API Key 和当前模型选择；移除独立的推理用途配置。

## 1. 目标与约束

1. DeepSeek 与 GLM-5.3 分别保存 API Key，作者可在设置页选择当前使用的模型。
2. 每次调用按当前选择的服务商和模型执行；草稿、正文、修改、评审、摘要等调用共用此选择。
3. 凭据按同一服务商优先读取设置页保存的 Key，再读取 `.env` 中的该服务商 Key。两处均无可用 Key 时，返回清楚的未配置错误。
4. 移除 `draft` / `reasoning` 两种模型用途路由。模型选择不再因为调用用途而变化。
5. 保留不同调用所需的温度、输出上限和超时等运行参数；这些是调用参数，不代表独立模型或推理用途。
6. API Key 不回显、不进入日志或普通 API 响应。用户设置的 Key 加密后持久化。

本文按当前本地单用户应用设计。“用户设置”指 Rill 设置页保存的应用设置；本次不引入注册、登录、账号隔离或多租户。

## 2. 当前实现

| 位置 | 当前行为 | 调整方向 |
| --- | --- | --- |

| `backend/src/ai/models/model.registry.ts` | 固定构造 `ChatDeepSeek` | 根据当前服务商构造模型客户端，并统一调用接口 |

## 3. 选择和调用语义

设置页保存的当前服务商与模型决定新调用使用的模型。选择是全局设置，不按项目、阶段或调用用途分别保存。

```text
用户选择 DeepSeek 或 GLM-5.3
            |
            v
开始一次 LlmService 调用
            |
            +--> 读取当前服务商和模型
            +--> 取该服务商的用户设置 Key
            |       无用户 Key 时读取对应 .env Key
            +--> 无 Key：返回未配置错误
            +--> 有 Key：创建本次模型客户端并调用
```

- 调用开始时读取一次设置和密钥，形成仅驻留内存的调用快照。本次重试及结构修复继续使用同一快照。
- 设置保存成功后开始的新调用使用新设置；已开始的调用不在中途切换模型或 Key。
- 不跨服务商自动回退。选中 GLM 时只解析 GLM 的用户 Key 和 `GLM_API_KEY`；选中 DeepSeek 时只解析 DeepSeek 的用户 Key 和 `DEEPSEEK_API_KEY`。
- 当前所选服务商的用户设置和 `.env` 均无 Key 时，拒绝该次调用并指出应配置哪个服务商。另一服务商的 Key 不构成可用凭据。
- 设置页的连通性测试验证当前已保存的选择。保存 Key 本身不调用模型。

## 4. API Key 保存和解析

### 4.1 持久化

用户在设置页保存的 Key 存入本地 SQLite 数据库，不写回 `.env`。建议新增单例模型设置记录，包含当前服务商、当前模型、每家服务商加密后的 Key、密钥版本和更新时间。

- 每家 Key 独立保存、替换和清除；清除用户设置的 Key 后，该服务商仍可使用 `.env` 中的 Key。
- 使用 AES-256-GCM 加密数据库中的用户 Key；每次加密生成新的随机 nonce，并保存认证标签和密钥版本。
- 加密主密钥通过后端环境变量 `LLM_CREDENTIAL_ENCRYPTION_KEY` 提供，不暴露给前端，也不由设置 API 修改。
- 若数据库中存在用户 Key，但加密主密钥缺失或解密失败，不静默降级到 `.env`。返回可诊断的配置错误，避免用户保存的 Key 损坏后意外使用另一把凭据。
- 对于首次迁移和仍在使用旧 `.env` 的本地安装，未配置数据库 Key 时继续使用环境变量，无需手动搬迁密钥。

### 4.2 环境变量

保留 DeepSeek 环境变量并增加 GLM 环境变量：

```dotenv
DEEPSEEK_API_KEY=
GLM_API_KEY=
LLM_CREDENTIAL_ENCRYPTION_KEY=
```

`.env.example` 只提供空占位和生成加密主密钥的说明。已有 `DEEPSEEK_BASE_URL` 可继续作为本地兼容配置；GLM 先使用官方固定兼容接口地址，避免设置页接受任意上游地址。

### 4.3 解析规则

解析仅针对当前选择的服务商：

```text
credential = decrypt(userSettings[provider].apiKey)
          ?? env[provider.apiKeyVariable]

credential 为空 -> 未配置错误
```

若用户显式清除 Key，则清除的是数据库中的用户 Key，环境变量仍按兜底规则生效。设置页分别显示“用户 Key 已配置”“使用环境变量”或“未配置”，不显示密钥内容。若保存了用户 Key，则优先级高于 `.env`，即使用户 Key 鉴权失败也不自动换用 `.env`；错误应提示用户更换或清除用户 Key。

## 5. 模型与客户端适配

### 5.1 服务商和模型

内部使用稳定的服务商标识 `deepseek`、`glm`，模型 ID 与展示名分开保存。首批模型为当前默认 DeepSeek 模型和 `glm-5.3`；模型 ID 应由后端受控目录提供，不接受前端任意拼接 API 地址或模型名。

智谱 GLM 采用其 OpenAI 兼容接口，官方示例给出的基础地址为 `https://open.bigmodel.cn/api/paas/v4/`，并以 `glm-5.3` 作为模型 ID。模型 ID、基础地址和调用参数集中在服务商适配配置中。官方文档提示接口仍有差异；其 temperature 范围为 `(0, 1)`，因此配置校验与适配层必须按服务商限制参数，不能直接复用 DeepSeek 的 `0–2` 范围。正式开放 GLM-5.3 选择前，需验证当前 API 账号有权限调用该模型，且普通文本、结构化输出、正文长度处理和 token 用量解析均符合 Rill 预期。

### 5.2 统一调用接口

`ModelRegistry` 按选择创建相应客户端，向 `LlmService` 暴露统一的文本和结构化输出能力。业务层继续调用 `complete()` / `completeStructured()`，不直接依赖具体 SDK。

- DeepSeek 继续使用现有 `ChatDeepSeek`。
- GLM 通过 OpenAI 兼容客户端接入；新增依赖时与现有 `@langchain/core` 版本对齐。
- 服务商特有参数仅在适配层设置。不得把 DeepSeek 专用 `thinking` 参数无条件传给 GLM。
- 结构化输出的 schema 校验、修复重试、调用预算、超时和取消行为由共享调用层维持。
- 用量记录使用响应中的实际模型标识；若供应商不返回 token 用量，按现有规则记录为未知/零值，不伪造费用。

GLM-5.3 的模型 ID、Base URL 和参数范围参考[智谱 OpenAI API 兼容文档](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。文档中的兼容示例不替代 Rill 对 LangChain 结构化输出和用量回调的实际验证。

### 5.3 移除推理用途

移除独立的 `reasoning` 用途和相应模型路由：

- `MODEL_USAGES`、`UsageConfig`、`AiConfig.usages.reasoning` 和 `LLM_REASONING_*` 环境配置。
- `CompleteOptions.usage`、`CompletionResult.usageKind` 及注册表中基于用途解析模型的逻辑。
- 正文评审中的 `usage: 'reasoning'`，改为使用当前所选模型的普通调用。
- `reasoning_content` 不再作为业务返回字段持久化或展示。若供应商响应仍包含此字段，适配层丢弃。

所有调用共用同一个当前服务商与模型。各业务调用仍可覆盖输出 token 上限和取消信号；温度、超时等通用参数保留一个默认配置，并允许有限的调用级覆盖。本文中的“去掉推理”指去掉独立推理模型/用途和推理内容消费，不改变提示词中要求模型分析问题的自然语言，也不把模型内部能力作为产品功能暴露。

## 6. 设置页与契约

设置页更名为“模型设置”，在 `/settings` 路由展示：

1. 当前服务商和模型选择。
2. DeepSeek Key 状态、密码输入、保存和清除。
3. GLM Key 状态、密码输入、保存和清除。
4. 当前有效 Key 来源：用户设置、`.env` 或未配置。
5. 当前模型连通性测试及明确的失败原因。

保存模型选择时允许暂存未配置的服务商，以便用户先选模型再补 Key；实际调用和连通性测试在解析不到该服务商的 Key 时提示配置缺失。保存 Key 不自动切换当前服务商。

共享契约至少包含：

- 查询：当前服务商、当前模型、可选模型目录、每家 Key 是否已保存、每家有效凭据来源。
- 选择更新：服务商 ID、模型 ID。
- Key 更新：服务商 ID、`replace` + Key 或 `remove`。
- API 查询不返回已保存 Key、加密内容、主密钥或 Key 片段。

凭据更新使用服务端 schema 校验和现有同源写入保护。设置查询和写入响应设置 `Cache-Control: no-store`。Key 不写入浏览器持久存储；保存成功后清空输入框。

## 7. 错误与安全

- 所选提供商没有用户 Key 或 `.env` Key：返回可操作的未配置错误，不发起网络请求。
- Key 格式错误或数据库加密错误：保存/读取阶段返回明确错误，不记录敏感值。
- 供应商鉴权失败：提示所选提供商的用户设置 Key 无效；不自动回退到 `.env` 或另一提供商。
- 模型不可用、限流和供应商服务错误：继续使用现有错误分类与重试策略。
- 错误日志只记录 traceId、服务商、模型和脱敏后的错误类别；禁止输出 Authorization 头、请求配置对象和完整上游错误体。
- 加密主密钥不得写进数据库、响应、日志、前端变量或版本控制。失去主密钥会导致数据库内用户 Key 无法恢复，应在部署文档说明备份与轮换责任。

## 8. 迁移和兼容

- 现存 `DEEPSEEK_API_KEY` 保持可用，自动成为 DeepSeek 用户设置缺失时的后备凭据。
- 数据库首次创建模型设置记录时，选择 DeepSeek 和现有默认模型，保证升级后行为与当前默认提供商一致。
- 删除 `reasoning` 配置读取后，旧 `.env` 中残留的 `LLM_REASONING_*` 变量可被忽略；文档和 `.env.example` 清理旧字段。
- 现存小说、检查点、阶段产物和用量数据不迁移、不重写。模型切换只影响后续新调用，不自动使既有产物失效。
- 用量记录结构如存有 `usageKind`，迁移时保留历史记录读取兼容；新记录只依赖实际模型名，不再产生 `reasoning` 标签。

## 9. 实施边界与验收

实现可分为四部分：

1. **配置与密钥**：增加用户设置持久化、加密和 provider-scoped 的用户设置优先 / `.env` 后备解析。
2. **调用层**：统一当前模型快照，接入 GLM 适配，去掉 reasoning 用途路由和推理内容字段。
3. **设置页与契约**：支持两家密钥、模型选择、有效来源状态和当前配置连通性验证。
4. **兼容与检查**：迁移 DeepSeek 默认设置，清理旧推理环境变量，确认模型和调用日志不泄密。

验收要点：

- 用户 Key 存在时优先使用用户 Key；用户 Key 缺失时使用同一 provider 的 `.env` Key。
- 两处均缺失时，调用返回可理解错误且没有网络请求；未选 provider 的密钥不参与回退。
- 用户 Key 替换/清除不改写 `.env`；清除后若 `.env` Key 存在则仍可调用。
- 设置页不回显 Key；日志、响应、用量、检查点中无明文 Key。
- 保存新模型后新调用使用新选择，已经开始的调用和内部重试保持原快照。
- 草稿、正文、评审、摘要、修改和结构化生成都使用所选模型；代码和配置不再要求 `reasoning` 用途。
- DeepSeek 和 GLM 的普通调用、结构化输出、失败分类和 token 用量分别验证；GLM 真实调用需使用用户自有 Key，并作为独立付费验收。

## 10. 未纳入范围

- 用户注册、登录、账号体系及多用户隔离。
- 项目级或阶段级模型选择、跨服务商自动故障切换。
- 任意自定义 Base URL、模型目录在线拉取、账单或平台代付。
- 新增推理用途、推理模型、推理内容展示或持久化。
- 自动重跑历史产物或因模型切换标记已有阶段 stale。
