# Proposal

## Why

现有流水线已能生成种子、世界观、人物与关系，但大纲阶段仍为占位，无法把设定转为可供细纲消费的完整故事安排。作者需要先编辑并确认全书规划，再逐段生成、编辑和确认每章概要，以便在写正文前控制主线与章节走向。

## What Changes

- 接入大纲阶段：全书规划 → 手动确认 → 分段展开章纲 → 完整大纲确认；自动模式连续执行。
- 允许作者设置正整数目标章数，未指定时采用篇幅默认值：短篇 8、中篇 40、长篇 200；模型不得自行改变目标章数。
- 全书规划包含主线、主要转折、高潮与结局、人物及关系发展、剧情分段和章数分配；章纲包含每章概要，场景与节拍留给后续细纲。
- 支持直接编辑全书规划与每章概要，保存与确认分开；修改规划使已有章纲及下游产物失效，修改章纲使下游产物失效。
- 持久化大纲内部进度、内容版本及分段结果；失败后只续跑未完成部分。
- 将已确认关系及必要的完整设定补入上游上下文，支持跳过世界观的类型。
- 在桌面工作台提供章数设置、规划及章纲编辑、内部步骤状态、错误与续跑反馈。

## Capabilities

### New Capabilities

- `outline-generation`: 两步大纲生成、章节规模、结构与语义校验、编辑确认、版本与分段续跑。

### Modified Capabilities

- `novel-pipeline`: 手动模式支持大纲阶段内确认，确认规划后仍停留大纲阶段，完整大纲确认后才推进。
- `novel-frontend`: 工作台支持大纲内部步骤、目标章数与结构化编辑，区分保存、确认规划和确认完整大纲。

## Impact

- `shared/src/index.ts`：大纲、编辑请求、内部状态、版本与关系上下文契约。
- 后端大纲模块、提示词注册表、上游装配、阶段定义、流水线图与确认入口；Prisma 新增大纲与分段记录及兼容迁移。
- 前端工作台与 API 客户端；后端单测、HTTP e2e、前端交互测试与人工真实调用验收。
- 依赖 `repair-pipeline-execution-safety` 的运行所有权、阶段状态与失效运行隔离；先完成该变更再接入大纲，不重复建设通用执行安全机制。
- 不包含细纲/正文生成、单章模型重写、章节拖拽重排或新增小说平台上传能力。
