# Proposal

## Why

Rill 已能生成并确认全书节拍，但正文仍为占位阶段。作者需要按章生成和确认正文，并能直接编辑本地 Markdown；修改前文后应保留后文，通过复核恢复续写，避免丢失创作成果。

## What Changes

- 以 `output/{project_id}/chapters/NNN.md` 为正文权威来源，SQLite 记录章节状态、哈希、确认和依赖版本。
- 每章正文生成后先 AI 审核，通过后生成待接受摘要，再由人接受正文与摘要；自动模式可自动执行机器步骤，但正文阶段仍逐章等待人工接受。
- 检测本地修改，撤销本章确认，使后续已有正文进入需复核状态，按顺序复核后继续。
- 审核覆盖七个维度，问题必须有证据；支持填写理由后强制接受 AI 未通过的正文，保留原判，摘要就绪后仍需最终人工接受。
- 提供候选稿、冲突保护、文件与数据库恢复对账，以及章节阅读和确认工作台。
- 将单章节拍变更与正文依赖联动，保留其他章节内容；明确后续正文需复核的语义。

## Capabilities

### New Capabilities

- `prose-generation`: 正文文件、章节生成、确认、摘要、外部修改检测、复核、冲突保护和恢复。

### Modified Capabilities

- `novel-pipeline`: 正文阶段的逐章确认、完成门槛和文件生命周期。
- `pipeline-graph-orchestration`: 正文阶段内部暂停、恢复及复核门禁。
- `novel-frontend`: 正文工作台和本地文件状态展示。
- `story-beats`: 单章节拍变更精确使该章正文失效，并使其后已有正文需复核。

## Impact

涉及 shared 契约、Prisma 迁移、`backend/src/novel/prose/`、阶段存储与装配、流水线图与运行预算、节拍失效调用、项目删除、控制器、前端 API 和正文工作台。新增应用管理的本地输出目录及忽略规则，不增加外部服务。

本变更依赖 `add-story-beats`：其规范现已同步到主规范（含 `story-beats`），实施前仍须核对本次 MODIFIED delta 的基线；本变更不改动其归档产物。
