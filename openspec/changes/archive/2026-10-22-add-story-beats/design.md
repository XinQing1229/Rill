# Design

## Context

`Stage` 已包含 `beats` 和 `prose`，类型阶段列表也预留了这两阶段，但当前仅实现到 `outline`。大纲保存在 `Outline` 与按分段持久化的 `OutlineBatch` 中；`contextFor` 只向下游暴露已确认且版本匹配的完整大纲。当前 `StageSnapshot`、`STAGE_STORAGE` 和前端阶段状态聚合尚无节拍产物适配。

节拍必须逐章编辑和重生成，同时长篇默认最多 200 章；因此存储、失败恢复和失效粒度需要支持单章，而整书确认仍是流水线阶段边界。

## Goals / Non-Goals

**Goals:**

- 为每个已确认大纲章节生成一组按因果顺序排列的事件节拍，支持单章保存、编辑和重生成。
- 支持部分章节完成、失败恢复、版本校验、整书确认及下游正文依赖。
- 遵循当前共享 zod 契约、StageGenerator、ArtifactRegistry、统一提示词注册及 token 用量记录模式。

**Non-Goals:**

- 不将节拍强行映射为场景、镜头或段落。
- 不在本变更中实现正文生成器、正文编辑器或场景拆分。
- 不改变大纲现有规划与逐章概要的结构和生成流程。

## Decisions

### 1. 以章节为持久化和重生成单位，整书为确认单位

新增每项目、每章节唯一的节拍记录，保存章节号、关联大纲 revision、JSON 节拍内容、状态、错误、stale 标记、revision 和 token 用量。节拍内容使用 zod schema 校验后序列化，章节记录可独立提交；阶段级确认版本保存在项目节拍进度记录或等价的阶段状态中。全书状态由目标章节与有效记录聚合，只有章节号连续覆盖大纲且全部成功、未失效时允许确认。

备选：将全书节拍放在一个 JSON 字段中。此方案数据模型较简单，但单章重生成需要整体读改写，难以隔离失败、并发编辑和陈旧结果，因此不采用。

### 2. 按篇幅分批调用模型，但节拍仍逐章归属

每次调用按篇幅分组：短篇将目标章数内的全部章节一次提交，中篇每批 3 章，长篇每批 5 章。调用携带这些章节概要、所属剧情分段、已确认全书规划及必要的角色/关系设定；输出仍为每章独立的节拍列表，绝不将多章合并成一个节拍。校验输出章节集合与批次完全一致、章号不重复、每章至少一个节拍、顺序连续且人物引用有效后，逐章持久化。节拍 schema 表达事件/行动、参与人物、阻碍或局势变化、结果/后续影响；数量不固定，提示词以约 3–5 个为起始建议但校验不依赖固定数目。

备选：一章一次调用会在长篇产生约 200 次请求，开销和总时长过高；多章共用一个节拍则会丢失章内事件细节。短篇目标章数较少，因此一次生成整本以保持连贯并减少操作；中长篇按批次兼顾请求成本和可恢复性。生成按章节顺序分批推进，每批成功后立即保存；失败重试跳过之前已完成的章节。节拍阶段运行预算按实际批次数扩展，避免沿用固定 10 分钟预算导致长篇被过早中断。

### 3. 节拍服务复用阶段执行和版本互斥机制

实现 `StageGenerator` 与专属服务，由 `StageContext` 读取已确认大纲和人物引用。生成、确认、重生成和保存均校验项目当前 run、阶段与 revision；旧运行的迟到输出不得写入。阶段间自动推进、手动暂停和回退复用现有 LangGraph 与流水线控制机制，不在节拍服务中另建运行器。

### 4. 失效精确到依赖章节，同时保留整书确认门槛

大纲版本或其上游改变时，所有节拍和正文失效；编辑/重生成单章节拍时只使该章正文失效，但会撤销整书节拍确认，整书重新确认后才继续推进。正文生成上下文只暴露当前大纲版本下整书已确认的节拍。

备选：任一单章编辑使全书所有节拍失效。此方案简单但会丢失不相关章节的作者工作；保留其他有效章节，仅撤销整书确认更符合逐章编辑模型。

### 5. 前端提供阶段导航和逐章工作台

在现有工作台阶段导航中启用节拍阶段，提供章节列表、章节节拍查看/编辑/排序、单章重生成、完成与失败进度，以及整书确认入口。阶段未就绪时沿用现有上游阻塞提示与项目运行状态；正文保持未实现阶段占位，直至后续变更。

## Risks / Trade-offs

- [短篇单次生成包含全部章节，输出规模高于分批调用] → 短篇目标章数有限；批次超时预算按实际请求数计算，失败时保留此前已完成的章节内容。
- [独立编辑的节拍可能破坏章间因果连贯] → 生成时注入全书规划和所属分段；确认前允许作者通读全部章节节拍。
- [更改上游后部分旧节拍仍保留于数据库] → 以关联大纲 revision 和 stale 状态限制读取，正文上下文只读取匹配的有效版本。

## Migration Plan

新增数据库迁移和阶段产物表；现有项目尚无节拍数据，迁移不需回填。部署后旧项目进入节拍阶段时按当前已确认大纲生成。若回滚应用，保留新增表数据但不再展示；不删除作者产物。
