# Spec Delta

## ADDED Requirements

### Requirement: 后端以 ESM 模块格式构建与运行

后端 SHALL 以 ECMAScript 模块（ESM）格式编译产物并加载运行，且构建、开发启动、测试三条链路在同一模块语义下均可用。后端 SHALL 拒绝缺少文件扩展名的相对模块导入，并在构建期而非运行期暴露该错误。

#### Scenario: 构建后端产物

- **WHEN** 开发者执行后端构建命令
- **THEN** 构建成功完成并产出可加载的后端产物
- **AND** 产物按 ESM 语义加载，不依赖 CommonJS 的 `require(esm)` 兜底

#### Scenario: 缺少扩展名的相对导入在构建期被拦截

- **WHEN** 后端源码中出现不带文件扩展名的相对模块导入
- **THEN** 构建过程以明确的编译错误失败并指出该导入
- **AND** 该错误在启动或调用服务之前暴露

#### Scenario: 开发服务器启动并提供接口

- **WHEN** 开发者执行项目文档中声明的开发启动命令
- **THEN** 后端服务以 ESM 产物启动并在其默认端口监听
- **AND** 请求健康检查端点返回表明服务存活的响应

#### Scenario: 后端测试全部通过

- **WHEN** 开发者执行后端测试命令（单元测试与端到端测试）
- **THEN** 全部既有测试用例在不修改断言语义的前提下通过
- **AND** 测试过程不产生模块格式相关的告警或错误

#### Scenario: 以生产方式启动后端

- **WHEN** 开发者执行后端的生产启动命令
- **THEN** 服务以 ESM 产物成功启动并对外提供接口

#### Scenario: 共享契约包继续被后端消费

- **WHEN** 后端以 ESM 运行并导入共享契约包中的类型校验 schema 与常量
- **THEN** 这些具名导出可正常解析并使用
- **AND** 共享契约包自身无需改变模块格式
