# Spec Delta

## MODIFIED Requirements

### Requirement: 执行进度持久化且可从中断处恢复

系统 SHALL 持久化保存流水线的执行进度及有效运行标识，使得服务重启或用户稍后返回时能从中断处继续。已失效或已取消的运行不得覆盖当前运行的进度与阶段产物。

#### Scenario: 重启后从中断处继续

- **WHEN** 服务重启后恢复此前未完成的流水线
- **THEN** 系统从持久化的中断处继续执行
- **AND** 不重复执行已完成阶段的生成

#### Scenario: 失败后从失败阶段继续

- **WHEN** 流水线在某一阶段失败
- **THEN** 系统保留该失败阶段为恢复起点
- **AND** 再次启动时不重复执行此前已完成阶段

#### Scenario: 过期运行尝试写入

- **WHEN** 一个运行标识已失效的执行尝试提交阶段结果
- **THEN** 系统拒绝该提交
- **AND** 当前有效运行的状态与结果保持不变

### Requirement: 以指定阶段为起点启动

系统 SHALL 支持以任一阶段作为起点启动流水线；首次生成、失败续跑、显式重新生成与回退后确认均须依据持久化阶段状态，正确恢复或推进，不得因 checkpoint 缺失而重复停留在同一已完成阶段。

#### Scenario: 回退后确认从下一阶段继续

- **WHEN** 用户回退到已完成阶段并确认推进
- **THEN** 系统执行流程中的下一阶段
- **AND** 已完成的回退目标不被重复执行

#### Scenario: 回退后从目标阶段重跑

- **WHEN** 用户回退到某一阶段后再次启动生成
- **THEN** 系统以该阶段为起点执行
- **AND** 该阶段之后的产物在被重新生成前保持失效状态

#### Scenario: 显式重新生成指定阶段

- **WHEN** 用户显式要求重新生成某一已完成阶段
- **THEN** 系统以该阶段为起点执行
- **AND** 重新生成该阶段产物
