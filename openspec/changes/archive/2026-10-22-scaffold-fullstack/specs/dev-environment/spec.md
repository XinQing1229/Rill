# Spec Delta

## Purpose

为 Rill 提供一键启动的全栈本地开发环境：前后端开发服务器、健康检查、经真实调用验证的 LLM 连通性，以及 API 密钥的安全管理。这是所有后续功能（大纲生成、章节创作、平台上传）共同的运行基础。

## ADDED Requirements

### Requirement: 单命令启动全栈开发环境

系统 SHALL 提供一个文档化的单命令入口，同时启动后端 API 服务与前端开发服务器，且两者均可在本地访问。

#### Scenario: 开发者启动开发环境

- **WHEN** 开发者在仓库根目录执行项目文档中声明的开发启动命令
- **THEN** 后端 API 服务启动并在其默认端口监听
- **AND** 前端开发服务器启动并在其默认端口监听
- **AND** 前端页面可访问

#### Scenario: 前端开发请求代理到后端

- **WHEN** 前端页面在后端端口不可用时发起 API 请求
- **THEN** 前端展示可读的连接错误，而非空白或未处理的崩溃

### Requirement: 后端健康检查端点

后端 SHALL 暴露一个健康检查端点，用于确认服务存活状态。

#### Scenario: 服务正常时查询健康状态

- **WHEN** 客户端请求健康检查端点
- **THEN** 系统返回成功状态码
- **AND** 响应体包含表明服务存活的状态信息

### Requirement: LLM 连通性验证端点

后端 SHALL 暴露一个连通性验证端点，使用环境配置中的 LLM 提供商设置发起一次真实调用，并返回调用结果。

#### Scenario: 配置有效时验证连通性

- **WHEN** 客户端请求连通性验证端点，且环境配置中的提供商地址、API 密钥与模型名均有效
- **THEN** 系统向配置的 LLM 提供商发起一次真实补全请求
- **AND** 返回本次调用的结果内容

#### Scenario: 配置缺失或无效时验证连通性

- **WHEN** 客户端请求连通性验证端点，但 API 密钥缺失或提供商拒绝请求
- **THEN** 系统返回描述失败原因的响应
- **AND** 响应中不包含 API 密钥本身

### Requirement: LLM 提供商配置通过环境变量管理

系统 SHALL 从环境配置中读取 LLM 提供商的接口地址、API 密钥与模型名，并提供一个不含真实密钥的配置模板文件。

#### Scenario: 开发者参照模板完成配置

- **WHEN** 开发者复制配置模板并填入有效的 API 密钥
- **THEN** 连通性验证端点使用该配置完成调用

#### Scenario: 仓库不包含真实密钥

- **WHEN** 检视仓库中所有被版本控制的文件
- **THEN** 不存在任何真实的 API 密钥
- **AND** 存放真实密钥的配置文件被版本控制忽略

### Requirement: API 密钥不出现在日志与响应中

系统 SHALL 保证 LLM 提供商的 API 密钥不被写入日志，也不在任何 API 响应中返回。

#### Scenario: 调用失败时排查日志

- **WHEN** 一次 LLM 调用因认证失败而出错，开发者查看服务日志
- **THEN** 日志中包含失败原因
- **AND** 日志中不包含 API 密钥

### Requirement: 前端应用外壳与连通性演示页面

前端 SHALL 渲染一个应用外壳页面，展示后端健康状态，并允许用户触发 LLM 连通性验证、查看返回结果。

#### Scenario: 用户打开演示页面

- **WHEN** 用户在浏览器中打开前端页面
- **THEN** 页面展示应用外壳布局
- **AND** 页面展示后端健康检查的结果

#### Scenario: 用户触发连通性验证

- **WHEN** 用户在页面上触发 LLM 连通性验证操作
- **THEN** 页面展示本次调用的返回结果，或展示可读的失败信息

### Requirement: 各工作区具备可运行的测试基线

系统的每个代码工作区 SHALL 包含至少一个可本地运行的测试，作为后续功能的测试基线。

#### Scenario: 开发者运行测试命令

- **WHEN** 开发者在仓库根目录执行测试命令
- **THEN** 各工作区的测试被依次执行
- **AND** 命令以成功退出码结束
