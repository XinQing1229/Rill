# Proposal

## Why

AI 基建（模型路由、结构化输出、重试与预算、用量埋点）已就绪，但项目还没有任何小说领域能力——一个字都写不出来。小说创作不是一次调用，而是「种子 → 世界观 → 人物 → 大纲 → 细纲 → 正文」的多阶段流程，且默认需要**人在环路**：每阶段生成后由作者确认再继续。这意味着阶段产物与推进状态必须跨请求持久化——只靠内存 state 在进程重启或用户隔天回来确认时就丢了。

同时，「类型每次选择、篇幅短篇起步并保留中长篇扩展」决定了流程不能写死：阶段列表、世界观详略、生成参数都应随类型与篇幅变化。

## What Changes

- 引入 Prisma + SQLite 持久化：建立 `Project` 聚合根与 `Premise`（种子）产物表，配置 `DATABASE_URL`，`*.db` 加入 `.gitignore`
- 新增类型配置（genre profile）：类型与篇幅共同决定阶段列表、世界观详略、建议章节字数与模板变量
- 新增创作流水线状态机：阶段枚举、产物状态（`pending` / `generating` / `done` / `failed` + `stale` 失效标记）、手动（默认）与自动两种模式
- 手动模式：每阶段生成后进入待确认，确认才推进；支持回退到已完成阶段，回退后下游产物标记为失效
- 自动模式：连续推进至完成；中途失败停在该阶段并标记失败，可从失败阶段重试而非从头再跑
- 并发与重复生成防护：`generating` 状态本身即锁；已完成阶段需显式指定才重新生成
- 生成异步化：生成接口立即返回，状态由状态机推进（为后续正文生成的长时间执行预留）
- 新增种子（Premise）生成能力：走 `completeStructured` + zod schema；提示词模板按阶段设计，类型特征作为变量注入，避免「阶段 × 类型」模板组合爆炸
- 种子生成前先收集**结构化问卷答案**（必答 4 项：类型、篇幅、基调、视角；其余选答，类型特有项级联出现）；用户已选维度直接落库、不交由模型生成，以消除冲突并提升一次命中率
- 记录每个阶段的 token 消耗，便于按项目统计成本
- 测试隔离：使用独立的 SQLite 数据库，避免污染开发数据

## Capabilities

### New Capabilities

- `novel-pipeline`: 小说创作流水线——项目与阶段状态的持久化、按类型与篇幅确定的阶段流程、手动/自动推进模式、重新生成与回退失效机制

### Modified Capabilities

（无——`ai-infrastructure` 的规范级行为不变，本次只是消费其 `completeStructured` 能力）

## Impact

- 后端新增依赖：`prisma`、`@prisma/client`；新增 `backend/prisma/schema.prisma` 与迁移
- 新增 `src/novel/` 模块：类型配置、流水线状态机、种子生成、Prisma 服务
- 新增 API：项目创建/查询、流水线推进（生成、确认、回退、模式切换）
- `@rill/shared` 新增种子阶段的 schema 与流水线相关契约类型
- 新增 `DATABASE_URL` 配置与 `.env.example` 条目；`*.db` 加入 `.gitignore`
- 构建流程需包含 `prisma generate`
- 无前端改动（前端界面属于后续 change）
