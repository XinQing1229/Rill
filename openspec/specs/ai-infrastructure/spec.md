# ai-infrastructure Specification

## Purpose
为后端提供统一的 AI 基建：按用途路由模型、以版本化模板管理提示词、产出经过校验的结构化数据、在失败时按错误类型重试并受总预算约束，并记录每次生成（含重试）的汇总用量、耗时与成本。后续所有小说生成能力都建立在这层之上。

## Requirements

### Requirement: 按用途路由模型配置

系统 SHALL 允许调用方按用途（草稿生成 / 重推理）选择模型配置；各用途的模型名、temperature、maxTokens、超时时间与思维链开关均来自配置。

#### Scenario: 草稿用途关闭思维链

- **WHEN** 调用方以草稿用途发起生成请求
- **THEN** 系统使用草稿用途配置的模型与参数完成调用
- **AND** 系统显式关闭思维链

#### Scenario: 重推理用途开启思维链

- **WHEN** 调用方以重推理用途发起生成请求
- **THEN** 系统使用重推理用途配置的模型与参数完成调用
- **AND** 系统显式开启思维链

### Requirement: 提示词以版本化模板渲染

系统 SHALL 通过命名且带版本号的模板渲染提示词，模板变量在渲染时校验。

#### Scenario: 使用指定模板与版本渲染

- **WHEN** 调用方指定模板名、版本号与变量发起渲染
- **THEN** 系统返回该模板版本渲染后的提示词内容

#### Scenario: 变量缺失时渲染失败

- **WHEN** 调用方传入的变量缺少模板要求的必填项
- **THEN** 系统在渲染阶段返回错误
- **AND** 不向模型发起任何调用

### Requirement: 按 schema 生成并校验结构化输出

系统 SHALL 支持调用方给出数据结构定义（schema），按该结构生成结果，并对模型返回内容做校验；结构化生成不启用思维链。

#### Scenario: 模型返回符合结构时返回结果对象

- **WHEN** 调用方以 schema 发起结构化生成请求，且模型返回内容符合该结构
- **THEN** 系统返回通过校验的结果对象

#### Scenario: 结构化生成时关闭思维链

- **WHEN** 调用方以任一用途发起结构化生成请求
- **THEN** 系统显式关闭思维链完成调用
- **AND** 返回结果符合给定 schema

#### Scenario: 校验失败时自动重试修复

- **WHEN** 模型首次返回的内容不符合 schema
- **THEN** 系统将校验错误信息回喂模型并重试
- **AND** 该修复重试的次数不超过配置上限

#### Scenario: 重试耗尽后返回明确错误

- **WHEN** 结构化生成在配置的修复重试次数内始终未通过校验
- **THEN** 系统返回描述失败原因的错误
- **AND** 错误信息中不包含 API 密钥

### Requirement: 失败按错误类型重试并受总预算约束

系统 SHALL 对不同失败类型采取不同策略：限流错误退避后重试、服务端错误重试、请求类错误不重试；且单次生成请求累计的模型调用次数不得超过配置的预算上限。

#### Scenario: 遭遇限流时退避重试

- **WHEN** 模型调用返回限流错误
- **THEN** 系统按退避策略等待后重试
- **AND** 重试次数不超过配置上限

#### Scenario: 遭遇请求类错误时不重试

- **WHEN** 模型调用返回请求参数类错误
- **THEN** 系统不重试并直接返回错误

#### Scenario: 总调用预算耗尽后停止

- **WHEN** 一次生成请求累计的模型调用次数达到配置的总预算上限
- **THEN** 系统停止重试并返回描述失败原因的错误
- **AND** 错误信息中不包含 API 密钥

### Requirement: 生成调用可追踪、用量汇总且不泄露密钥

系统 SHALL 为每次生成调用分配可追踪的标识，并汇总该次调用（含全部重试）的模型、token 用量、耗时与费用估算；密钥不得写入日志。

#### Scenario: 记录汇总后的用量与耗时

- **WHEN** 一次生成调用结束（成功或失败，含重试）
- **THEN** 系统在同一追踪标识下记录汇总后的 token 数、总耗时与费用估算

#### Scenario: 日志中不出现密钥

- **WHEN** 调用因认证失败而报错，开发者查看服务日志
- **THEN** 日志中包含失败原因与追踪标识
- **AND** 日志中不包含 API 密钥
